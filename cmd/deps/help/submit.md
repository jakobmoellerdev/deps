Extracts every dependency (no lookups, no network apart from the submission) and submits them to GitHub's dependency graph as one snapshot (the [dependency submission API](https://docs.github.com/en/rest/dependency-graph/dependency-submission)): one manifest per file, one package URL per dependency. GitHub then shows them in *Insights → Dependency graph*, includes them in the SBOM export and in dependency review, and raises Dependabot alerts for the ecosystems of its advisory database.

**What is submitted.** By default only the files GitHub does not read by itself: Gradle builds and version catalogs, the Maven and Gradle wrappers, Dockerfiles, Compose files, Kubernetes and Helm YAML and other image references, custom (annotation and regex) dependencies, and the other managers whose datasource has a package URL type. go.mod, package.json, the Python manifests, Cargo.toml, pom.xml and workflows are left out, because GitHub parses them itself (with the full resolved graph for Go and Python) and a submitted manifest replaces GitHub's view of that file; `--all-managers` submits them too.

**Package URLs** by datasource: `go` → `pkg:golang/<module>`, `npm` → `pkg:npm/<name>` (`%40scope/name`), `pypi` → `pkg:pypi/<name>`, `crate` → `pkg:cargo/<name>`, `maven` → `pkg:maven/<group>/<artifact>`, `github-releases` (github.com) → `pkg:github/<owner>/<repo>`, `docker` → `pkg:docker/<path>` (with `?repository_url=<registry>` outside Docker Hub), GitHub Actions → `pkg:githubactions/<owner>/<repo>`; the version is the locked one when a lockfile has it, else the one written. Deps without a concrete version (ranges, variables, templates) and datasources without a purl type (helm, terraform, node and Go toolchain versions, git tags) are left out. Deps ignored by policy (ignored by default, or by a rule) are real dependencies and are submitted. Every dependency is `direct`; `devDependencies`, dev groups and `test` deps have scope `development`, the rest `runtime`.

**Snapshot fields**: `job.correlator` is `<GITHUB_WORKFLOW> <GITHUB_JOB> deps`, so each workflow job keeps its own latest snapshot; `job.id` is `GITHUB_RUN_ID`; `sha` and `ref` are `GITHUB_SHA` and `GITHUB_REF`; the detector is `deps` with its version.

The token needs `contents: write` (`GITHUB_TOKEN` works). Outside GitHub Actions, and on Gitea and Forgejo, `submit` exits 2; `--dry-run` prints the snapshot as JSON to stdout instead, anywhere.

Output lines (stderr): `manifest  <file>  <count>` per manifest, `submitted <result>` (`SUCCESS`, or `ACCEPTED` when GitHub queues it), `error   <message>` per file that failed to parse, and `<n> dependencies in <m> manifests, <e> errors`.
